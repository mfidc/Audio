## What exact workflow, file layout, skill set or memory setup does each publish, in enough detail that someone could copy it?

### Takeaway
The copyable setups converge on a small number of moves: interrogate the human before building (Pocock's grilling, superpowers' brainstorming, gstack's /office-hours), write the plan and domain vocabulary to plain files, give the agent a fast verification loop (types, tests, a CLI or browser), keep always-loaded context tiny and disclose the rest on demand, and store memory as small, bounded, human-readable Markdown. The authors differ sharply on how much process to impose: Pocock, Zechner and Steinberger argue for minimal, hackable pieces, while gstack and superpowers ship a full mandatory pipeline.

#### Matt Pocock (skills repo, AI Hero)
Source record: Matt Pocock, "Skills For Real Engineers" (mattpocock/skills), GitHub repo README, undated living doc read 23 Nov 2026, https://github.com/mattpocock/skills
- [V] Repo shows 330.9k stars, 27.8k forks, MIT, 559 commits. — [GitHub](https://github.com/mattpocock/skills)
- [V] Positioning: "My agent skills that I use every day to do real engineering - not vibe coding." He contrasts them with GSD, BMAD and Spec-Kit, which "try to help by owning the process" and so "take away your control and make bugs in the process hard to resolve"; his are "small, easy to adapt, and composable" and "work with any model". — [README](https://github.com/mattpocock/skills)
- [V] Install: `claude plugin install mattpocock-skills@claude-plugins-official` (self-updating), or `npx skills@latest add mattpocock/skills -a <agent>` for editable copies; pick one, because both gives every skill twice. Then run `/setup-matt-pocock-skills` once per repo: it asks which issue tracker (GitHub, GitLab, local files), which triage labels, and where docs are saved. — [README](https://github.com/mattpocock/skills)
- [V] Four failure modes and his fix for each: (1) misalignment → a grilling session (`/grill-me` for non-code, `/grill-with-docs` for code), "use them every time you want to make a change"; (2) verbosity → a shared-language glossary (`GLOSSARY.md`, previously `CONTEXT.md`) plus ADRs, built inside `/grill-with-docs`; (3) code doesn't work → feedback loops (static types, browser access, automated tests) and a red-green-refactor `/tdd` skill plus `/diagnosing-bugs`; (4) ball of mud → `/to-spec` asks which modules are touched and `/improve-codebase-architecture` should be run "once every few days". — [README](https://github.com/mattpocock/skills)
- [V] Example of the glossary effect he gives: "There's a problem when a lesson inside a section of a course is made 'real'..." becomes "There's a problem with the materialization cascade". Claimed side benefits: consistent naming, easier navigation, fewer thinking tokens. — [README](https://github.com/mattpocock/skills)
- [V] Skill inventory. Engineering, user-invoked: ask-matt (router), grill-with-docs, triage, improve-codebase-architecture, setup-matt-pocock-skills, to-spec, to-tickets (tracer-bullet tickets with blocking edges), implement, implement-spec (subagents across the "ready frontier"), wayfinder (work too big for one session, as decision tickets), retro. Engineering, model-invoked: prototype, diagnosing-bugs, research, tdd, domain-modeling, codebase-design (Ousterhout "deep modules"), code-review (two parallel sub-agents: Standards and Spec), pr, wizard. Productivity: grill-me, handoff, teach, to-questionnaire, wait-what, grilling, writing-for-agents. — [README](https://github.com/mattpocock/skills)
- [V] Design rule: user-invoked skills orchestrate and are reachable only by typing them; model-invoked skills hold reusable discipline; "a user-invoked skill may invoke model-invoked skills, but never another user-invoked one." — [README](https://github.com/mattpocock/skills)
- [V] The `grilling` skill text: map decisions as a "design tree"; each round ask the whole "frontier" (every question whose prerequisites are settled), numbered, each with a recommended answer and worded "so 'yes' accepts your recommended answer"; "Finding facts is your job, never the user's" (dispatch a fresh-context sub-agent to look things up); do not act until the user confirms shared understanding. — [grilling/SKILL.md](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)
- [V] The `writing-for-agents` skill is his most detailed advice on skills and AGENTS.md/CLAUDE.md: a skill description or AGENTS.md line is a "context pointer" whose wording, not its target, decides when the agent loads material; two budgets, "context load" (always-loaded tokens) and "cognitive load" (the human as index); an information hierarchy of in-file step → in-file reference → disclosed reference; every step ends on a checkable, exhaustive "completion criterion" to prevent "premature completion"; use "leading words" already in pretraining (tracer bullets, red, tight) instead of sentences; steer with positive instructions because negation "drags the forbidden behaviour into context"; do not restate what the environment already says (package.json scripts, --help), "cache what the agent cannot find by looking"; prune "sediment". — [writing-for-agents/SKILL.md](https://github.com/mattpocock/skills/blob/main/skills/productivity/writing-for-agents/SKILL.md)
- [S] AI Hero pages say `/grill-me` exists because Claude Code in plan mode "tends to spit out a plan really early"; it should be started in a fresh conversation rather than on top of an existing plan; the idea is credited to Anthropic's Thariq Shihipar by a third-party source. — [AI Hero: grill-me](https://www.aihero.dev/use-the-grill-me-skill-k029d), [AI Hero: skills-grilling](https://www.aihero.dev/skills-grilling)
- [S] Pragmatic Engineer podcast "AI Skills with Matt Pocock" (podcast index dates it 17 Sept 2026) covers why grill-me caught on, software fundamentals, local vs cloud workflows and whether agents need TDD; a third-party index summarises his argument that tracer bullets, vertical slices and DDD act as "leading words". — [Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/ai-skills-with-matt-pocock)
- [S] Thoughtworks Technology Radar has an entry for mattpocock/skills. — [Thoughtworks Radar](https://www.thoughtworks.com/de-de/radar/tools/mattpocock-skills)

#### David Crawshaw and Philip Zeyliger (sketch.dev, now exe.dev / Shelley)
Source records: David Crawshaw, "How I program with Agents", blog essay, 8 June 2025, https://crawshaw.io/blog/programming-with-agents ; David Crawshaw, "Eight more months of agents", blog essay, 8 Feb 2026, https://crawshaw.io/blog/eight-more-months-of-agents ; Philip Zeyliger, "The Unreasonable Effectiveness of an LLM Agent Loop with Tool Use", sketch.dev / blog.philz.dev post, about May 2025; boldsoftware/sketch README, https://github.com/boldsoftware/sketch ; boldsoftware/shelley README, https://github.com/boldsoftware/shelley
- [S] Crawshaw's definition: "an agent is a for loop which contains an LLM call. The LLM can execute commands and see their output without a human in the loop." His worked example is implementing GitHub App auth for sketch.dev. — [crawshaw.io](https://crawshaw.io/blog/programming-with-agents)
- [S] Zeyliger's post shows a roughly nine-line loop with tool schemas (notably bash) driving complex work, the model even installing missing utilities; caveat noted in a mirror: brittleness, skipped work when tests fail. Author attribution rests on the blog.philz.dev domain, not on a page I read. — [engineered.at mirror summary](https://engineered.at/articles/the-unreasonable-effectiveness-of-an-llm-agent-loop-with-tool-use), [HN thread](https://hn.nuxt.dev/item/43998472)
- [V] Sketch's published design: run `sketch` in a git repo; it creates and builds a Dockerfile, copies the repo in, runs the agent inside the container and outputs work onto a branch in the host repo; this "lets you run multiple sketches in parallel" and "it can trash its own container, but it can't trash your machine"; the loop uses "mostly shell commands, but also a handful of other important tools". — [sketch README](https://github.com/boldsoftware/sketch)
- [V] OUTDATED: "Sketch is no longer maintained"; it "has evolved into Shelley". Shelley is "a mobile-friendly, web-based, multi-conversation, multi-modal, multi-model, single-user coding agent" that "does not come with authorization or sandboxing: bring your own." — [sketch README](https://github.com/boldsoftware/sketch), [shelley README](https://github.com/boldsoftware/shelley)
- [S] Feb 2026 advice: use the best frontier model ("if you try some penny-saving cheap model like Sonnet, or a second rate local model, you do worse than waste your time, you learn the wrong lessons"); he no longer uses an IDE ("In 2021, the IDE had won. In 2026, I don't use an IDE any more"), keeping only go-to-definition in neovim; built-in sandboxes get in the way so "you have to provide your own sandbox ... I highly recommend: use a fresh VM", which is why he is building exe.dev. — [crawshaw.io](https://crawshaw.io/blog/eight-more-months-of-agents), [Simon Willison, 7 Feb 2026](https://feeds.simonwillison.net/2026/Feb/7/david-crawshaw/)

#### Garry Tan (gstack)
Source record: Garry Tan, gstack README and docs/why-gstack.md, GitHub repo, living docs read 23 Nov 2026 (why-gstack cites figures "through April 18" 2026), https://github.com/garrytan/gstack
- [V] 142.4k stars, 21.0k forks, MIT. "All slash commands, all Markdown." — [GitHub](https://github.com/garrytan/gstack)
- [V] Install: clone to `~/.claude/skills/gstack` and run `./setup`, then add a "gstack" section to CLAUDE.md telling Claude to use gstack's `/browse` for all web browsing. Requires Claude Code, Git and Bun. Team mode: `./setup --team` plus `gstack-team-init required|optional`, committed to the repo, with a throttled auto-update check each session. Other hosts via `./setup --host codex|cursor|opencode|...`; only Claude Code is tier "full" with hook-enforced safety skills, others are "experimental" and "advisory, not blocked". — [README](https://github.com/garrytan/gstack)
- [V] The process is "Think → Plan → Build → Review → Test → Ship → Reflect"; "gstack is a process, not a collection of tools", and each skill reads what the previous one wrote (`/office-hours` writes a design doc that `/plan-ceo-review` reads; `/plan-eng-review` writes a test plan `/qa` picks up; `/review` findings are checked by `/ship`). — [README](https://github.com/garrytan/gstack)
- [V] Core skills and what they do: `/office-hours` (six forcing questions, pushes back on framing, writes design doc); `/plan-ceo-review` (four modes: Expansion, Selective Expansion, Hold Scope, Reduction); `/plan-eng-review` (architecture, data flow diagrams, edge cases, test matrix); `/plan-design-review` (0-10 per dimension, "AI Slop detection"); `/review` (bugs that pass CI, auto-fixes obvious ones, flags every weakened test/timeout/suppression "by name"); `/qa` (real browser, reproduces bugs, writes failing regression, fixes); `/cso` (security audit); `/ship` (sync main, tests, coverage audit, PR); `/land-and-deploy`; `/canary`; `/retro`; `/learn` (review, prune and export cross-session learnings); `/autoplan` (CEO → design → DX → eng review, surfacing only taste decisions); `/careful`, `/freeze`, `/guard` safety modes; `/codex` or `/claude-code` for a cross-model second opinion. why-gstack.md counts "Twenty-three specialists and eight power tools"; the current README table lists roughly 40 commands. — [README](https://github.com/garrytan/gstack)
- [V] Recommended on-ramp: `/office-hours`, then `/plan-ceo-review`, `/review` on any branch, `/qa` on staging, "Stop there. You'll know if this is for you." By default it proactively suggests only four skills (office-hours, review, qa, ship). — [README](https://github.com/garrytan/gstack), [why-gstack.md](https://github.com/garrytan/gstack/blob/main/docs/why-gstack.md)
- [V] His own usage: 10-15 parallel sprints via Conductor ("that's the practical max right now"); "/qa was a massive unlock. It let me go from 6 to 12 parallel workers"; "Without a process, ten agents is ten sources of chaos"; "100% test coverage is the goal — tests make vibe coding safe instead of yolo coding." — [why-gstack.md](https://github.com/garrytan/gstack/blob/main/docs/why-gstack.md)
- [V] gstack maps itself onto Karpathy's four failure modes (wrong assumptions, overcomplexity, orthogonal edits, imperative over declarative). Its `/write-skill` skill encodes a five-step edit ladder: "fix the tool first, add nothing the model already does, edit the line instead of appending, lowest level that reaches the agent, rule not story". — [why-gstack.md](https://github.com/garrytan/gstack/blob/main/docs/why-gstack.md), [README](https://github.com/garrytan/gstack)

#### Jesse Vincent (superpowers)
Source records: Jesse Vincent / Prime Radiant, obra/superpowers README, RELEASE-NOTES.md and skill files, GitHub repo, latest release v7.0.2 dated 3 Nov 2026, https://github.com/obra/superpowers ; Jesse Vincent, "Superpowers: How I'm using coding agents in October 2025", blog post, 9 Oct 2025, https://blog.fsck.com/2025/10/09/superpowers/ ; prime-radiant-inc/superpowers-evals README, https://github.com/prime-radiant-inc/superpowers-evals
- [V] 324.6k stars, 28.8k forks, MIT. Install in Claude Code: `/plugin install superpowers@claude-plugins-official`; also packaged for Codex, Cursor, Gemini CLI, Copilot CLI, OpenCode, Pi, Hermes and others. — [GitHub](https://github.com/obra/superpowers)
- [V] The seven-step workflow, each a skill that auto-triggers: (1) brainstorming (questions, plays understanding back; small changes agreed in chat, projects get a written design doc); (2) using-git-worktrees (isolated branch, verify clean test baseline); (3) writing-plans ("bite-sized tasks (2-5 minutes each). Every task has exact file paths, complete code, verification steps"); (4) subagent-driven-development (fresh subagent per task with review after each, "most thorough") or executing-plans (inline, one final review, "cheapest"); (5) test-driven-development ("Deletes code written before tests"); (6) requesting-code-review (critical issues block progress); (7) finishing-a-development-branch (merge/PR/keep/discard). "Mandatory workflows, not suggestions." — [README](https://github.com/obra/superpowers)
- [V] The plan is written to be "clear enough for an enthusiastic junior engineer with poor taste, no judgement, no project context, and an aversion to testing to follow"; "It's not uncommon for your agent to work autonomously for a couple hours at a time without deviating from the plan." — [README](https://github.com/obra/superpowers)
- [V] Other skills: systematic-debugging (4-phase root cause), verification-before-completion, dispatching-parallel-agents, receiving-code-review, writing-skills, using-superpowers, diagnosing-superpowers (reads the session transcript to explain why a skill misfired). Philosophy: "Test-Driven Development", "Systematic over ad-hoc", "Complexity reduction", "Evidence over claims". — [README](https://github.com/obra/superpowers)
- [V] The bootstrap skill is forceful: "If you think there is even a 1% chance a skill might apply to what you are doing, you ABSOLUTELY MUST invoke the skill"; skill check comes "BEFORE any response or action — including clarifying questions"; it includes a "Red Flags" table of rationalisations ("This is just a simple question" → "Questions are tasks. Check for skills."). Process skills (brainstorming, systematic-debugging) take priority over implementation skills. It is injected by a SessionStart hook and again after compaction. — [using-superpowers/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/using-superpowers/SKILL.md), [README](https://github.com/obra/superpowers)
- [V] His method for writing skills is TDD applied to documentation: run a pressure scenario with a subagent without the skill and "document exact rationalizations agent uses" (RED), write the minimal skill addressing those violations (GREEN), then close loopholes (REFACTOR). "If you didn't watch an agent fail without the skill, you don't know if the skill teaches the right thing." — [writing-skills/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/writing-skills/SKILL.md)
- [V] Skill-authoring rules in that file: a description "says only when to use it ... starting with 'Use when...'. It never summarizes the skill's workflow, because an agent that reads a workflow summary follows it instead of reading the skill"; do not create skills for one-off solutions, project-specific conventions (those go in the instructions file), or anything enforceable by regex/validation ("automate it—save documentation for judgment calls"); flat namespace, one `SKILL.md` per folder, separate files only for 100+ line reference or reusable scripts. — [writing-skills/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/writing-skills/SKILL.md)
- [V] The project does not generally accept contributed skills, requires changes to work across all supported agents, and tests skill behaviour with its own "drill"/Quorum eval harness that drives real agent CLIs and grades "workflow compliance: skill triggering, worktree behavior, subagent coordination, verification reflexes, review quality, and cost-shaping patterns". — [README](https://github.com/obra/superpowers), [superpowers-evals README](https://github.com/prime-radiant-inc/superpowers-evals)
- [S] His blog in mid-2026 lists posts on "The Therapist Pattern" and "Some new agentic patterns", and a v5.x release run from March 2026 mentioning subagent reviewers. — [blog.fsck.com](https://blog.fsck.com/)
- [B] The October 2025 launch post described using persuasion principles (Cialdini-style authority, commitment, social proof) to make skills stick and pressure-testing skills against subagents; a `persuasion-principles.md` file I expected in the repo was not at that path on 23 Nov 2026. — [launch post](https://blog.fsck.com/2025/10/09/superpowers/)

#### Nous Research (hermes-agent)
Source record: Nous Research, hermes-agent README and docs (memory.md, skills.md), GitHub repo, read 23 Nov 2026, https://github.com/NousResearch/hermes-agent
- [V] 265.6k stars, 60.1k forks, MIT. Pitch: "the only agent with a built-in learning loop — it creates skills from experience, improves them during use, nudges itself to persist knowledge, searches its own past conversations, and builds a deepening model of who you are". — [GitHub](https://github.com/NousResearch/hermes-agent)
- [V] Memory layout: two files in `~/.hermes/memories/`, `MEMORY.md` (agent's notes; hard limit 2,200 characters, about 800 tokens) and `USER.md` (user profile; 1,375 characters, about 500 tokens), injected into the system prompt as a "frozen snapshot at session start"; entries separated by `§`; header shows percentage used. Memory "does not auto-compact": an over-limit write returns an error and the agent must consolidate. The snapshot is frozen to preserve the prompt cache, so a fact saved mid-session only appears next session. — [memory.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md)
- [V] What to save: user preferences, environment facts, corrections, conventions, completed work, explicit requests. What to skip: trivial info, easily re-discovered facts, raw data dumps, session-specific ephemera, anything already in SOUL.md/AGENTS.md. — [memory.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md)
- [V] Recommended practice: "run `/new` at natural boundaries — a finished task, a change of topic, the start of a day", because the memory machinery pays off only at session boundaries; older context is recovered with a `session_search` tool (SQLite FTS5 plus LLM summarisation). — [memory.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md), [README](https://github.com/NousResearch/hermes-agent)
- [V] Skills as "procedural memory": the agent creates, updates and deletes its own skills via `skill_manage` when it "worked out a multi-step workflow worth repeating", "hit errors or dead ends and found the working path", or "the user corrected its approach"; a skill should capture "lessons, not logs". Memory holds "small durable facts that should always be in context" while skills hold "longer procedures that should load only when relevant". A background review after a turn and a "curator" consolidation pass can also write. — [skills.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md)
- [V] Controls: `write_approval: true` requires human approval before memory or skill writes; project skills in cloned repos are not auto-loaded and are security-scanned; one agent process per Hermes home. — [memory.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md), [skills.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md)

- [S] Every's stated loop is plan, work, review, compound, with "roughly 80 percent of compound engineering ... in the plan and review parts"; the review command spawns many specialised reviewers in parallel (14 per one guide). Shipper's framing is an "AI sandwich": humans frame the problem and check the output, agents do the middle. — [Every guide](https://every.to/guides/compound-engineering), [AI & I episode](https://pocketcasts.com/podcast/ai-and-i/baa88660-780c-013c-9fa1-0acc26574db2/the-ai-sandwich-where-humans-excel-in-an-ai-world/a972cc9d-86a2-4d53-a7bd-2e71bd322ce2)

### Inferences
- Three independent authors (Pocock, Vincent, Tan) open with the same step, an interview that forces the human to state intent before any code, which suggests this is the highest-agreement practice in the set.
- Memory designs from Hermes, OpenClaw and Torres share a shape: a tiny always-loaded profile, a curated long-term file, raw daily or session logs searched on demand, and a periodic consolidation pass. claude-mem automates the same shape with a database instead of files.
- "Progressive disclosure" appears under different names in Pocock (context pointers), Larson, Böckeler (lazy-loaded skills), Zechner (a 225-token README), Torres (index files) and claude-mem (index, timeline, details). The common rule is that always-loaded text should be a short pointer, with detail fetched only when a branch needs it.
- Steinberger's AGENTS.MD and Pocock's writing-for-agents converge on the same split: the instruction file holds hard rules only, and procedures live in skills.
- The minimalists (Zechner, Steinberger, Crawshaw, Ball) all report using few or no MCP servers and few personal skills, relying on CLIs the model already knows.

## What do they say fails, and what did they change their mind about?

### Takeaway
The failures they report cluster around context (pollution, bloated instruction files, MCP tool descriptions, long threads), unverified work (no feedback loop, premature "done"), and over-trusting agents to find their own context. The clearest reversals are Steinberger dropping plan mode, slash commands and session restarts as models improved; Crawshaw abandoning the IDE and concluding harnesses matter less than the model; the claude-mem author withdrawing a "10x token savings" claim; and Husain and Shankar renaming error analysis to error discovery and warning against handing traces to an agent unguided.

### Cited Findings

#### What fails
- [V] Pocock: the four recurring failures are misalignment, verbosity from missing shared vocabulary, code that does not work for lack of feedback loops, and accelerated "software entropy" ("Most apps built with agents are complex and hard to change"). Process frameworks that "own the process" make "bugs in the process hard to resolve". — [mattpocock/skills README](https://github.com/mattpocock/skills)
- [V] Pocock on instruction writing: vague completion criteria invite "premature completion"; prohibitions make the banned behaviour "more available, not less"; documents rot into "sediment" because "adding feels safe and removing feels risky". — [writing-for-agents/SKILL.md](https://github.com/mattpocock/skills/blob/main/skills/productivity/writing-for-agents/SKILL.md)
- [V] Vincent: a skill description that summarises the workflow fails because the agent "follows it instead of reading the skill"; skills written without first observing baseline failure may teach the wrong thing; on Hermes, a long session that compacts over its first turn "loses the bootstrap" and skills stop triggering. — [writing-skills/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/writing-skills/SKILL.md), [superpowers README](https://github.com/obra/superpowers)
- [V] Zechner: "models are still poor at finding all the context needed for implementing a new feature or fixing a bug", which he attributes to models reading only parts of files; many PRs to his repo "get closed or revised because the agents couldn't fully grasp what's needed ... we trust our agents too much"; built-in sub-agents are "a black box within a black box" with poor context transfer; built-in to-do lists "confuse models more than they help"; large MCP servers burn 7-9% of the window before work starts. — [pi post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)
- [V] Jason Liu: "bad context is cheap but toxic"; "Most teams waste months building agent frameworks before they know if their idea actually works"; "Teams fail because they don't commit to outcomes" (wrong form factor). — [slash-commands post](https://github.com/jxnl/blog/blob/main/docs/writing/posts/context-engineering-slash-commands-subagents.md), [prototyping post](https://github.com/jxnl/blog/blob/main/docs/writing/posts/context-engineering-agent-prototyping.md), [index](https://github.com/jxnl/blog/blob/main/docs/writing/posts/context-engineering-index.md)
- [V] Hermes docs: small local models (roughly under 30B parameters) and models with weak tool-calling often "produce the confirmation without the tool call", claiming a memory save that never happened; two agents sharing one home "compound each other's entries into state neither of them (nor you) authored"; the background review can save "a wrong assumption about me", for which the remedy is `write_approval: true`. — [memory.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md)
- [V] Tan: "Without a process, ten agents is ten sources of chaos"; raw lines of code are inflated by AI ("LLMs generate verbose code by default"). — [why-gstack.md](https://github.com/garrytan/gstack/blob/main/docs/why-gstack.md), [ON_THE_LOC_CONTROVERSY.md](https://github.com/garrytan/gstack/blob/main/docs/ON_THE_LOC_CONTROVERSY.md)
- [V] Steinberger: Opus-era models were "much more eager ... often doesn't read the whole file or misses parts"; picking dependencies, frameworks and system design remain hard and are where his own thinking goes; Codex's tool-output limit "fails silently"; two sessions touching the same files need care. — [post source](https://github.com/steipete/steipete.me/blob/main/src/content/blog/2025/shipping-at-inference-speed.md)
- [S] Larson: LLM-driven workflows failed to consistently perform deterministic tasks such as identifying merged pull requests (secondary summary); workflows with many tool calls or large files run out of context; teams can "focus on creating the impression of adopting AI, rather than focusing on creating additional productivity." — [fooqux summary](https://fooqux.com/article/1611), [lethain.com](https://lethain.com/company-ai-adoption/)
- [S] Ball: long threads make the model forget early instructions or enter "doom loops". — [ampcode.com](https://ampcode.com/notes/how-i-use-amp)
- [S] Crawshaw: weak or cheap models teach "the wrong lessons"; built-in sandboxes have to be turned off to get work done. — [crawshaw.io](https://crawshaw.io/blog/eight-more-months-of-agents)
- [S] Theo: auto-generated CLAUDE.md/AGENTS.md files slow agents and duplicate what is in the code; ThePrimeagen: agents ignore existing patterns, write verbose tests and accumulate inconsistencies. — [rosetta.to](https://rosetta.to/u/t3dotgg/delete-your-claude-md-and-your-agent-md-too), [wordspike](https://wordspike-website.pages.dev/s/ephYfbyFoAf)
- [S] Every: in a Claws-only channel two agents independently wrote the same specification; told to update their operating rules, the agents drafted an approval process in which each asks its own human. Shipper admits he tends to rush the planning step because reading LLM-written plans is boring. — [Every](https://every.to/context-window/five-ai-agents-walk-into-a-group-chat)
- [S] Husain and Shankar warn against "handing an agent a folder of traces and asking it to find problems" without first specifying which failure modes matter, citing a 100-trace study; "criteria drift" means teams learn what they want only after seeing the agent act. — [Lenny's Newsletter](https://lennysnewsletter.com/p/advanced-evals-how-to-find-and-fix), [Arize](https://arize.com/blog/rise-of-the-ai-engineer-why-ai-evals-fail-before-the-evaluation-begins/)
- [S] Security failure modes around personal agents: identity and memory files (SOUL.md, MEMORY.md) can be poisoned so attacks "persist across session restarts"; a Cisco test found a third-party skill doing exfiltration and prompt injection. OpenClaw itself calls prompt injection "still an industry-wide unsolved problem". — [Cloud Security Alliance note](https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/06/CSA_research_note_openclaw_indirect_prompt_injection_20260613-csa-styled.pdf), [MIT Technology Review](https://www.technologyreview.com/2026/02/11/1132768/is-a-secure-ai-assistant-possible/amp/)
- [V] OpenClaw's memory docs show the countermeasure now built in: workspace files recorded as untrusted are excluded from automatic memory context and listed by `openclaw doctor`. — [memory docs](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory.md)

#### What they changed their mind about
- [V] Steinberger (Dec 2025): plan mode "feels like a hack that was necessary for older generations of models"; "I used to be really diligent to restart a session for new tasks. With GPT 5.2 this is no longer needed"; prompts "gotten much shorter" after long dictated ones; "I used to play with slash commands, but just never found them too useful. Skills replaced some of it"; he took time to look into skills "after dismissing that idea for quite some time"; his `oracle` escalation tool went from "multiple times per day to a few times per week" as models improved; he tried async cloud agents and went back to the terminal because he "missed the steerability". — [post source](https://github.com/steipete/steipete.me/blob/main/src/content/blog/2025/shipping-at-inference-speed.md)
- [S] Crawshaw (Feb 2026): "Agent harnesses have not improved much since then. There are things Sketch could do well six months ago that the most popular agents cannot do today"; "Right now, it is all about the model"; he stopped using an IDE; Sketch itself was retired in favour of Shelley. — [crawshaw.io](https://crawshaw.io/blog/eight-more-months-of-agents), [sketch README](https://github.com/boldsoftware/sketch)
- [V] Zechner: he left Claude Code because it "has turned into a spaceship with 80% of functionality I have no use for"; his own benchmark moderated his MCP scepticism ("MCP vs CLI truly is a wash" on success rate and cost), after which his objection narrowed to context overhead and composability. — [pi post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/), [MCP vs CLI post](https://mariozechner.at/posts/2025-08-15-mcp-vs-cli/)
- [V] Jason Liu added a January 2026 update saying slash commands have become skills and subagents are mainstream. — [slash-commands post](https://github.com/jxnl/blog/blob/main/docs/writing/posts/context-engineering-slash-commands-subagents.md)
- [S] Larson: subagents were not an early priority ("just hadn't found subagents to be particularly important to our current workflows") but became useful once workflows were code-driven. — [lethain.com](https://lethain.com/agents-subagents/)
- [S] Böckeler describes the field moving from monolithic rules files and MCP servers to lazy-loaded skills, CLIs and scripts. — [InfoQ](https://infoq.com/podcasts/mcp-vibe-coding-harness-engineering)
- [S] Husain and Shankar renamed "error analysis" to "error discovery" in Sept 2026 "because the goal is to identify failures that are worth measuring". — [Lenny's Newsletter](https://lennysnewsletter.com/p/advanced-evals-how-to-find-and-fix)
- [V] Pocock renamed his glossary convention from `CONTEXT.md` to `GLOSSARY.md`. — [mattpocock/skills README](https://github.com/mattpocock/skills)
- [V] Tan conceded that "LOC is a garbage metric" and that "AI inflates LOC", and switched to a deflated "logical lines" measure. — [ON_THE_LOC_CONTROVERSY.md](https://github.com/garrytan/gstack/blob/main/docs/ON_THE_LOC_CONTROVERSY.md)
- [V] Newman reworded claude-mem's "~10x token savings" claim after a user challenge (see next section). — [claude-mem issue 4138](https://github.com/thedotmack/claude-mem/issues/4138)
- [S] Theo is inconsistent rather than reversed: alongside "delete your CLAUDE.md" he has tweeted about spending hours hand-writing better CLAUDE.md/AGENTS.md files and half a dozen skills. — [PostHog newsletter](https://posthog.com/newsletter/fix-your-agents)

### Inferences
- Several reversals track model capability rather than taste: plan mode, session restarts, long prompts and escalation tools were scaffolding for weaker models. Advice dated before late 2025 that depends on those crutches should be treated as provisional.
- The disagreement about sub-agents is about timing more than principle. Liu and Larson use them to keep noisy work off the main thread; Zechner objects to using them mid-session as a substitute for gathering context up front; both sides agree a review sub-agent with a fresh context is worthwhile.
- The "delete your instruction file" position and the "write hard rules only" position are compatible: both target auto-generated or duplicated content, and both keep what the agent cannot discover from the code.

### Gaps
- Ptacek's later views (after November 2025) were not found; no 2026 agent post by him surfaced.
- Koomen has no retrievable follow-up stating what he changed his mind about.
- The Larson "Evals to validate workflows" post body was not retrievable, so his account of what evals failed to catch is missing.
- A Theo video titled "Prime is right about AI" appeared in one aggregator listing but could not be confirmed.

## For the skill and memory packs: what is in them, and is there any independent evidence they help?

### Takeaway
The packs are overwhelmingly Markdown instructions plus a few hooks or helper binaries; their contents are well documented, but independent evidence that they improve outcomes is thin and mixed. The strongest outside signals are cautionary: an academic audit found many popular skills fail to beat a bare agent while adding cost, a controlled comparison on martinfowler.com found a harness helped a cheap model but only added cost for a frontier model, and claude-mem's maintainer withdrew an unmeasured savings claim.

### Cited Findings

#### What is in each pack (summary; details in the first section)
- [V] mattpocock/skills (330.9k stars): 27 small Markdown skills listed in the README (20 engineering, 7 productivity), a per-repo setup skill, no hooks or mandatory pipeline. — [GitHub](https://github.com/mattpocock/skills)
- [V] obra/superpowers (324.6k stars): about 15 skills plus a SessionStart bootstrap that makes skill checks mandatory; a brainstorm → worktree → plan → subagent execution → TDD → review → finish pipeline. — [GitHub](https://github.com/obra/superpowers)
- [V] garrytan/gstack (142.4k stars): roughly 40 role-based slash commands ("Twenty-three specialists and eight power tools" in its own older count), a bundled headless Chromium browser tool, safety hooks on Claude Code, a local prompt-injection classifier for its browser sidebar, cross-model review, and a learnings store. — [GitHub](https://github.com/garrytan/gstack)
- [V] thedotmack/claude-mem (119.2k stars): lifecycle hooks, a local worker, an observer model, SQLite plus Chroma, three-step search via MCP, a web viewer, optional paid hosted observer and team sharing. — [GitHub](https://github.com/thedotmack/claude-mem)
- [V] NousResearch/hermes-agent (265.6k stars): a full agent harness (not a pack) with two bounded memory files, session search, agent-authored skills with a curator, cron scheduling, messaging gateways and six terminal backends. — [GitHub](https://github.com/NousResearch/hermes-agent)
- [V] EveryInc/compound-engineering-plugin: 38 skills around a brainstorm, plan, build, review, capture loop. — [GitHub](https://github.com/EveryInc/compound-engineering-plugin)
- [V] obsidianmd/obsidian-skills: seven format and CLI skills. ai-evals-course/evals-skills: nine eval-building skills. — [obsidian-skills](https://github.com/kepano/obsidian-skills), [evals-skills](https://github.com/ai-evals-course/evals-skills)

#### Independent or semi-independent evidence
- [S] OpenSkillEval (arXiv 2605.23657; Ying, Ai, Tang, Liu, Cao; submitted 22 May 2026): over 600 generated task instances and 30 open-source skills across presentation, front-end design, poster, data-visualisation and report tasks. Findings: "many popular skills still fail to outperform base agents while introducing additional cost"; agents explicitly read the provided skill in only about 48% of cases on average under realistic access; benefit "depends heavily on the model and agent framework"; a weaker model with well-designed skills can match a stronger one. It is not established from the excerpts whether superpowers, gstack or Pocock's skills were among the 30, and the task categories are not software engineering. — [arXiv](https://arxiv.org/abs/2605.23657), [alphaXiv](https://www.alphaxiv.org/abs/2605.23657)
- [S] "Are Harnesses Worth the Cost?" (martinfowler.com, 13 Oct 2026): building the same API service with and without a behavioural harness of guides and sensors, 10 runs per condition. Frontier model (reported as GPT-6 Sol): 10/10 success both ways, but the harness used about 10.5 times the tokens, nearly 3 times the time and about 7 times the cost. Cost-optimised model (GPT-6 Luna): 3/10 without the harness, 10/10 with it. The author notes results might differ with a less complete brief. — [martinfowler.com](https://martinfowler.com/articles/are-harnesses-worth-the-cost.html)
- [S] ETH Zurich study on repository context files (arXiv 2602.11988 per secondary sources) is reported as finding AGENTS.md/CLAUDE.md files often reduce task success by about 3% and raise cost; this bears on packs that add always-loaded instructions. — [contextstream.io](https://contextstream.io/blog/a-new-study-says-delete-your-claude-md-agents-md-here-s-what-actually-works-instead), [Addy Osmani](https://addyosmani.com/blog/audit-your-agent-files/)
- [S] superpowers: an unattributed benchmark site ranks it 9th of 9 overall (weak on bugfix and refactor, competitive on feature tasks), with methodology and independence unverified; a practitioner test on a physics-modelling task found it useful for planning and debugging but noted "It is difficult to isolate how much of the outcome is attributable to the 'Superpowers' layer versus the underlying capabilities of Claude Code itself." — [claude-tool-benchmark](https://claude-tool-benchmark.pages.dev/preview/tool-superpower), [GAI Team](https://gai-team.pages.dev/resources/tool-evaluation-1)
- [V] superpowers' own eval lab measures workflow compliance (did the skill trigger, was the worktree used, was verification done), and says of itself "This is not a generic benchmark suite." That is evidence the skills change behaviour, not that outcomes improve. — [superpowers-evals README](https://github.com/prime-radiant-inc/superpowers-evals)
- [S] gstack: TechCrunch (17 Mar 2026) reported the split reaction: critics called it "a bunch of prompts" (Mo Bitar's video "AI is making CEOs delusional") and said it drew attention because of Tan's position (Sherveen Mashayekhi on Product Hunt: "if you weren't the CEO of YC, this wouldn't be on PH"); Tan's "god mode" security claims "drew sharp criticism"; supporters praise the insistence on review before shipping. No controlled comparison of output quality was found. — [TechCrunch](https://www.techcrunch.com/2026/03/17/why-garry-tans-claude-code-setup-has-gotten-so-much-love-and-hate/)
- [V] gstack's own evidence is self-reported: "~810× my 2013 pace (11,417 vs 14 logical lines/day)" across 40 of his repos, produced by his own script, with the admission that "LOC is a garbage metric". — [why-gstack.md](https://github.com/garrytan/gstack/blob/main/docs/why-gstack.md), [ON_THE_LOC_CONTROVERSY.md](https://github.com/garrytan/gstack/blob/main/docs/ON_THE_LOC_CONTROVERSY.md)
- [V] claude-mem: in issue 4138 (opened 20 Sep 2026) users challenged the README's "~10x token savings" claim as valid only with high search recall, noting "The README publishes no recall figure"; on 10-11 Nov 2026 the maintainer replied that the figure "isn't a measured recall number" and replaced it with "an index row is about a tenth the size of a full record, which is a size ratio, not a measured saving". The README now says exactly that. No recall measurement was added. — [issue 4138](https://github.com/thedotmack/claude-mem/issues/4138), [README](https://github.com/thedotmack/claude-mem)
- [S] claude-mem hands-on tests: one found the first request in an empty project cost 7,470 tokens without it and 12,228 with only its MCP server, a fixed overhead mostly absorbed by caching; in a controlled feature build all memory variants succeeded and wall time was the same ("the memory worked but at a cost"); another found recall lossy rather than verbatim and that installation sets `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, replacing Claude Code's built-in memory. An older analysis of v9.x estimated about 42,000 cache-creation tokens per session (OUTDATED, version has changed). — [HackerNoon test](https://hackernoon.com/claude-mem-tested-perfect-recall-but-at-a-cost-of-5200-tokens-per-request), [DEV critique](https://dev.to/veltrea_code/-reading-yc-backed-code-1-claude-mem-great-idea-poor-implementation-2mbi)
- [S] hermes-agent: reviews are favourable but thin; one cites a "40% speed improvement" visible only "after consistent use in a narrow domain", with no independent benchmark behind it; reviewers note a wrong assumption "can become a persistent context just as easily as a useful one". DeepLearning.AI's The Batch says it "differs primarily in its memory architecture and ability to build skills automatically". — [DEV review](https://dev.to/jangwook_kim_e31e7291ad98/hermes-agent-review-self-improving-open-source-ai-agent-3kk3), [The Batch](https://www.deeplearning.ai/the-batch/hermes-agent-challenges-openclaw), [eWeek](https://www.eweek.com/news/hermes-agent-self-improving-ai-tools/)
- [V] Zechner's own controlled test is evidence on a related packaging question: the same tool as MCP server or CLI gave identical 100% success and near-identical cost, so the choice mattered less than tool design. — [MCP vs CLI post](https://mariozechner.at/posts/2025-08-15-mcp-vs-cli/)
- [S] PostHog reports that an agent's effectiveness declined as skill descriptions filled its context window, a cost that applies to any large pack. — [PostHog newsletter](https://posthog.com/newsletter/writing-agent-skills)
- [S] Recognition without measurement: Thoughtworks Technology Radar lists mattpocock/skills; several packs are in Anthropic's official plugin marketplace. — [Thoughtworks Radar](https://www.thoughtworks.com/de-de/radar/tools/mattpocock-skills)

### Inferences
- Star counts in the hundreds of thousands are not evidence of effect. None of the five most-starred packs is backed by a public, independent, controlled comparison of task outcomes on software work.
- The Fowler-site result and OpenSkillEval point the same way: scaffolding helps weaker or cheaper models most and can be pure overhead on frontier models. A team on a top model should expect the benefit of heavy packs to come from process discipline for the human, not from higher task success.
- The 48% skill-read rate explains why superpowers and gstack invest in forced triggering (bootstrap hooks, mandatory language) and why Pocock stresses pointer wording: a skill that is not loaded cannot help.
- Smaller packs that add little always-loaded context (Pocock's, Obsidian's, the evals skills) carry less downside risk than pipelines that inject instructions every session.
- For memory, the only measured effects found were token overhead and unchanged task success; the benefit claimed is continuity and convenience, which the tests did not quantify.

### Gaps
- Whether OpenSkillEval's 30 skills include any of the packs studied here is unknown; the paper could not be opened.
- The author and full methodology of "Are Harnesses Worth the Cost?" were not confirmed; only search excerpts were available.
- No independent evaluation of mattpocock/skills, compound-engineering, obsidian-skills or evals-skills was found.
- No published results from the superpowers-evals harness (pass rates with and without skills) were located in its README.
- Hermes's self-authored skills have no located study of quality drift over time.
- GitHub API access was unavailable, so creation and last-commit dates for the repos are missing; only star, fork and licence figures from the repo pages are recorded.
